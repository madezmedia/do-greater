What the 25 donated Mac Studios can become, and what else is on the table

Triggered by Brianna's mention of the Mac Studio donation. Three things below: what to actually deploy on that hardware, verification that the Google Ad Grant really is still unclaimed, and a wider net of grants/credits worth chasing beyond it.

The Mac Studio fleet

25 donated Mac Studios is real, substantial Apple Silicon compute sitting idle. This is not generic homelab advice — it's the one project that's a direct match for both the hardware and Do Greater's own "Code the City" AI curriculum.

exo — cluster the Studios into one inference pool

Best fit

Open-source (exolabs.net / exo-explore) — pools multiple Apple Silicon Macs into a single distributed AI inference cluster. Devices auto-discover each other on the network; models get sharded across all 25 machines. On macOS 26.2 it supports RDMA over Thunderbolt 5, cutting inter-device latency ~99% — real reported numbers: 1.8x speedup on 2 devices, 3.2x on 4. A cluster this size could run frontier-scale open models (DeepSeek V3.1 671B, Kimi K2) entirely in-house, zero cloud bill. Exposes OpenAI/Claude/Ollama-compatible APIs, so anything already built against those SDKs works against it unchanged.

The story write-itself angle: Designathon already teaches kids to build with AI. A self-hosted cluster the org fully owns — that the same kids could tour, or even help operate — is a stronger asset than any cloud subscription.

Supporting self-hosted stack

Everything below is 2026-current, actively maintained, and Docker Compose-deployable — the standard "homelab AI stack" pattern right now:

exo Ollama Open WebUI n8n Portainer Coolify Qdrant (RAG) SearxNG (private search) ComfyUI (image gen)

Portainer or Coolify for fleet/container management across the 25 machines · Open WebUI as the actual chat interface staff and students use · n8n for the automation pipelines (the same follow-up/lead-capture gap flagged in the Coach Mac brief could run on this, at zero marginal cost) · Qdrant if any program wants retrieval over Do Greater's own documents/curriculum.

Networking note

Worth deciding early

25 machines clustering well needs either physical Thunderbolt daisy-chaining (best performance, only practical for machines in the same room) or a flat, fast local network plus something like Tailscale if any Studios end up split across Sparkhouse Uptown and Sparkhouse West. Worth settling this before buying any switches/cabling.
